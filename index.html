      Profiles

      Start from the person, not the settings.

      Eight presets in the same order as UserWay's, so visitors moving between sites find what they already know. A profile replaces the previous one rather than stacking on it, and choosing it again puts the page back.

      How it works

      Mostly CSS. Script only where CSS genuinely can't.

      Attributes on <html>

      Presentation tools are data-mla-* attributes plus one injected stylesheet, so they survive a client-side route change with nothing to re-apply. This is this page's root element, right now:

      document.documentElement
      
          
      
        
      

        
      
          
          
      Measured, not flattened
      
          
      
            Bigger text scales each element from its own computed size, so headings stay bigger
            than body. A blanket font-size: 20px !important is what gets that wrong.
          
      
        
      

        
      
          
          
      Contrast that keeps the design
      
          
      
            Smart contrast finds each text's real background and moves the colour along its own
            lightness axis until it passes WCAG 1.4.3. Grey stays grey, just darker.
          
      
          
      This line fails at about 2.1:1. Turn on Smart contrast.
      
        
      

        
      
          
          
      Sealed in a shadow root
      
          
      
            The widget is one custom element. Your CSS cannot restyle the panel, and the
            widget's own !important rules cannot reach in and eat it.

      What it won't claim
      
        
      
          No overlay makes a site compliant.
      
          This one doesn't pretend to.
        
      
      
      
      
      
        
      
          01
          
      Not a compliance fix
      
          
      It changes presentation at runtime. It cannot repair heading order, unlabelled
            controls, or components a screen reader can't drive. The 2024 Title II rule has no
            overlay safe harbour.
      
        
      
        
      
          02
          
      Not a screen reader
      
          
      Read aloud is a reading aid for sighted visitors. People who rely on assistive
            technology use NVDA, JAWS or VoiceOver, and those need correct markup underneath.
      
        
      
        
      
          03
          
      No AI alt text
      
          
      On purpose. Patching labels at runtime hides the problem. Fix them in the source,
            and let an axe check in your end-to-end suite keep them fixed.
      
        
      
      
      
    
      
  
      

  
  
      
    
      
      
      
        
      Privacy
      
        
      What leaves the browser. All of it.
      
        
      
          A visitor's settings live in localStorage under access-layer:v1.
          There is no analytics, no beacon and no visitor account. Two tools can reach the
          network, and only when a visitor asks them to.
        
      
      
      
      
        
        
      1. 
          Page load
          The script, from getaccesslayer.pages.dev.
          No third party
        
        2. 
        
      2. 
          Any setting
          Saved in this browser only, under one key.
          Stays local
        
        3. 
        
      3. 
          Dictionary
          The one word looked up goes to Wiktionary, and only while the tool is on.
          On request
        
        4. 
        
      4.

          On request

      Install
      
        
      One tag. That's the integration.
      
        
      
          Copy a ready tag from the console, or write one by hand: embed a
          pinned release with its integrity hash and configure it with
          data-* attributes. Every release keeps its own address forever;
          /v1/ follows the newest 1.x for pages that should update on their own.
        
      
        
      
          Pin the version on checkout and account pages, so the browser runs only the file you reviewed.
        
      
        Build a tag in the console
      
      

      
      
        
      
          
          
          
          
        
      
        
      
          
      index.html
      
          
      <!-- The release notes carry the exact integrity hash. -->
<script src="https://getaccesslayer.pages.dev/v1.0.0/access-layer.iife.js"
        integrity="sha384-…" crossorigin="anonymous" defer
        data-access-layer
        data-fonts-url="https://getaccesslayer.pages.dev/v1.0.0/fonts/"
        data-color="#1742C9"
        data-statement-url="/accessibility"></script>
      
        
      
        
      
          
      index.html
      
          
      <!-- Your button opens the panel and the floating
     icon stays hidden. -->
<script src="https://getaccesslayer.pages.dev/v1/access-layer.iife.js"
        defer data-access-layer
        data-trigger-id="accessibility-button"></script>

<button id="accessibility-button" type="button">
  Accessibility options
</button>
      
        
      
        
      
          
      plugins/access-layer.client.ts
      
          
      import { defineNuxtPlugin } from '#imports'

export default defineNuxtPlugin(() => {
  const script = document.createElement('script')
  script.src = 'https://getaccesslayer.pages.dev/v1/access-layer.iife.js'
  script.defer = true
  script.dataset.accessLayer = ''
  script.dataset.color = '#1742C9'
  document.body.append(script)
})
      
        
      
        
      
          
      main.js
      
          
      import { mount } from 'access-layer'

const widget = mount({ color: '#1742C9', statementUrl: '/accessibility' })

widget.settings.setProfile('dyslexia')
widget.settings.subscribe((state) => console.log(state))
